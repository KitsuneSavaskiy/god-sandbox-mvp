# GodSandbox 初回体験UXジャーニー

PBI-UX-FIRST-TIME-GODSANDDBOX-JOURNEY-001 対応ドキュメント

この文書は、GodSandbox を初めて触るユーザーが「これは何のゲームか」「次に何をすればよいか」を理解するための情報設計メモです。

実装は行いません。UIデザインの直接模倣、画像追加、`src/**`、`sample-games/**`、package、CI workflow の変更はこのPBIでは扱いません。

---

## 結論

GodSandbox は、AIキャラクターを観察し、声をかけ、介入し、成長させ、Character Passport として外へ持ち出す箱庭ゲームです。

初見ユーザーには、最初の30秒で「キャラを見守る」「次の行動を選ぶ」「変化を確認する」「外へ持ち出せる」の4点だけを伝えるべきです。

---

## 事実

- GodSandbox には、キャラクター、会話、観察、介入イベント、Character Passport export という要素がある。
- Character Passport は、キャラクターを後続ゲームや外部ツールへ渡すための安定JSONインターフェースとして整理されている。
- iOS Safari / Android Chrome 向けには、まず Web公開URLで遊べる Mobile Web readiness を優先する方針になっている。
- スマホ初見ユーザーは、広いダッシュボードよりも、縦に並んだカードと大きな次アクションを手がかりに進む可能性が高い。
- desktopでは、観察情報、状態、履歴、操作を広く見せるダッシュボード型の価値がある。

---

## 判断

- 初回画面では、世界観説明を長く読ませるより、現在の目的と次の行動を先に見せる。
- スマホでは、重要操作をカード末尾または画面下付近に置き、縦スクロール中でも次に進みやすくする。
- 進行状況、イベント発生、報酬、変化は、それぞれ短いカードに分けて判断しやすくする。
- 介入イベントでは、選択肢の意味、影響、まだ保留できるかを明示する。
- desktopでは、スマホと同じ情報を広く並べ、観察ダッシュボードとして扱う。
- 特定の既存ゲームの文言、画像、配色、固有演出は参考にしない。参考にするのは、ホーム、ミッション、イベント、CTAという一般的な情報設計だけにする。

## 初見向けの一文説明

候補A:

> GodSandbox は、AIキャラクターを箱庭で見守り、声をかけ、成長させ、別のゲームへ連れて行くための育成サンドボックスです。

候補B:

> あなたは小さな箱庭の神様として、AIキャラクターの行動を観察し、介入し、育ったキャラを Character Passport として外へ持ち出します。

推奨:

> GodSandbox は、AIキャラクターを箱庭で見守り、声をかけ、成長させ、別のゲームへ連れて行くための育成サンドボックスです。

理由:

- 「何をするゲームか」が短く分かる。
- Character Passport を知らない人にも、外へ持ち出す目的が伝わる。
- 神様視点の世界観は後から補足できる。

---

## 最初の30秒で理解すべきこと

初見ユーザーに最初から全部を説明しない。最初の30秒では、次の順で理解できればよい。

1. これはAIキャラクターを育てる箱庭である。
2. 画面には、今のキャラと状態が表示されている。
3. ユーザーは、観察、声かけ、介入のどれかを選べる。
4. 介入イベントが起きたら、選択肢から反応を決める。
5. キャラの変化は、成長やPassportに残る。
6. 育ったキャラは、別のゲームやサンプルへ持ち出せる。

最初の30秒で伝えなくてよいもの:

- Domain model の詳細
- Faith / Growth の内部計算
- LLM provider設定
- BYOK / BYOM の詳細
- Character Passport JSON の全field
- sample battle の戦闘ルール

## スマホ初期画面で見せる情報順

スマホは縦スクロール前提にする。初期画面では、上から順に次の情報を置く。

1. 一文説明カード
2. 現在のキャラカード
3. 今日の目的カード
4. 大きな次アクションCTA
5. 現在地カード
6. 進行状況カード
7. 最近の変化カード
8. Character Passport への短い案内カード

### 1. 一文説明カード

表示内容:

- GodSandbox の一文説明
- 「まずはキャラを見守り、次の一手を選びましょう」という短い案内

目的:

- 初見ユーザーが、画面を閉じる前にゲームの目的を理解できるようにする。

### 2. 現在のキャラカード

表示内容:

- キャラ名
- 画像または立ち絵
- ひとこと紹介
- いまの気分や状態を短く表示

目的:

- ユーザーが「このキャラに関わるゲームだ」と理解する。

### 3. 今日の目的カード

表示内容:

- 例: 「Ryoの様子を見て、次の行動を1つ選ぶ」
- 例: 「介入イベントが出たら、どう関わるか決める」

目的:

- 何を達成すればよいかを、短いミッションとして見せる。

### 4. 大きな次アクションCTA

表示内容:

- 「キャラを見守る」
- 「声をかける」
- 「介入イベントを見る」
- 「次の変化を確認する」

目的:

- 初見ユーザーに迷わせない。
- 画面下やカード末尾で親指操作しやすい位置に置く。

### 5. 現在地カード

表示内容:

- 「いまは観察中」
- 「介入イベントが発生中」
- 「Passportを確認できます」

目的:

- ユーザーが自分の状態を見失わないようにする。

### 6. 進行状況カード

表示内容:

- 今日の行動数
- 最近の変化数
- Passportに反映された要素

目的:

- 進んでいる感覚を作る。

### 7. 最近の変化カード

表示内容:

- キャラが反応した内容
- 成長した点
- 次に観察したい点

目的:

- ユーザーの行動がキャラに影響したと分かるようにする。

### 8. Character Passport 案内カード

表示内容:

- 「育ったキャラは、紹介カードとして外へ持ち出せます」
- 「別のゲームでは、仲間、敵、NPC、カードなど自由に使えます」

目的:

- GodSandbox の中核価値である外部連携を早めに見せる。

## 次アクションCTA案

CTAは1画面に複数出しすぎない。初見では主CTAを1つ、補助CTAを1つまでにする。

### 初回起動直後

主CTA:

- 「キャラを見守る」

補助CTA:

- 「このゲームの流れを見る」

### キャラ状態確認後

主CTA:

- 「声をかける」

補助CTA:

- 「もう少し観察する」

### 介入イベント発生時

主CTA:

- 「選択肢を決める」

補助CTA:

- 「あとで決める」

### Passport確認時

主CTA:

- 「キャラ情報をコピー」

補助CTA:

- 「サンプルゲームで使う流れを見る」

## 介入イベント時の意思決定UX

介入イベントは、初見ユーザーが最も迷いやすい場面です。

イベントカードには、次の順で情報を置く。

1. 何が起きたか
2. キャラが困っていること
3. ユーザーが決めること
4. 選択肢
5. 選択した場合の短い見込み
6. 保留できるかどうか

### イベントカード例

見出し:

> Ryoが森の奥へ進もうとしています

状況:

> Ryoは何かを探しているようです。ただし、道は暗く、少し危険そうです。

ユーザーが決めること:

> 進ませるか、止めるか、声をかけるかを選びます。

選択肢:

- 「進ませる」: 新しい発見があるかもしれません。
- 「止める」: 安全を優先します。
- 「声をかける」: Ryoの考えを聞きます。

保留:

> 迷う場合は、あとで決めても大丈夫です。

### 避けること

- 内部パラメータ名だけで判断させる。
- 成功率だけを見せる。
- 選択肢の意味を説明せずに押させる。
- 取り返しがつくかどうかを隠す。

## desktopでの見せ方

desktopでは、スマホと同じ内容を横に広げる。

推奨構成:

- 左: キャラカードと現在地
- 中央: 箱庭表示と次アクション
- 右: 進行状況、最近の変化、Passport案内
- 下: イベント履歴、観察ログ

desktopでは、情報を隠しすぎず、ダッシュボードとして全体像を見せる。

ただし、主CTAは常に1つ目立たせる。情報が多くても、次に押すものが分かる状態を維持する。

---

## 文言方針

使う表現:

- 「キャラを見守る」
- 「声をかける」
- 「次の一手を選ぶ」
- 「変化を確認する」
- 「キャラ情報をコピー」
- 「別のゲームへ連れて行く」

避ける表現:

- 「schemaをparse」
- 「domain model mapping」
- 「provider payload」
- 「internal state」
- 「成功率だけで命令する」

技術語が必要な場合は、先にやさしい説明を書く。

例:

> Character Passport は、キャラクターを別のゲームへ連れて行くための紹介カードです。

その後で、必要な人向けに「JSONとして保存できます」と補足する。
