# 神託回数・神様ポイント・新個体発見の中長期ループ設計

## この文書の目的

GodSandbox に、短い観察と介入のループだけで終わらない中長期ループを与える。

今回の設計対象は次の4つです。

- 神託回数を有限リソースにする
- 神様ポイントの獲得と消費のループを作る
- 報酬アイテム交換の意味を作る
- 新個体発見に「見つけた感覚」を与える

この文書は実装ではない。

- `src/**`、`server/**`、`sample-games/**` は変更しない
- DB / 保存形式変更は扱わない
- Passport schema 変更は扱わない
- package / CI / 課金 / ガチャ / 確率テーブルは扱わない

---

## 先に結論

GodSandbox の中長期ループは、次の形にするのがよい。

```text
観察する
↓
イベントが起きる
↓
Watch で見守るか、神託回数を使って Bless / Test する
↓
観察結果、発見、節目で神様ポイントを得る
↓
神様ポイントで回復アイテムや探索アイテムと交換する
↓
新個体を発見し、観察対象とイベントの幅が広がる
↓
次の観察と介入が少し有利になる
```

この設計で重要なのは、神託回数を有限化して「いつ介入するか」を判断させることです。

もし神託回数が無限のままだと、次の価値が弱くなる。

- Watch して記録を貯める意味
- 神様ポイントを稼ぐ意味
- 回復アイテムを買う意味
- 新個体を探す意味

---

## なぜ神託回数を有限化するのか

神託回数を有限化する目的は、単なる足止めではない。

目的は次の4つです。

1. 介入に重みを持たせる
2. Watch を「消極策」ではなく「次に備える選択肢」にする
3. 神様ポイントと報酬アイテムを意味のある報酬にする
4. 新個体発見を、観察対象を増やす戦略行為に変える

GodSandbox は、全部を最初から自由に触れるゲームにするより、神が限られた力で箱庭を見守る構造の方が作品体験に合う。

## MVPで入れる最小ループ

MVPでは、複雑な経済や保存より先に、次の最小ループだけ成立させる。

| 項目 | MVPで入れること |
|---|---|
| 神託回数 | `Bless` / `Test` にだけ消費を付ける |
| Watch | コスト 0 の退避行動として残す |
| 自然回復 | 時間経過で少しずつ回復する |
| 神様ポイント | 観察、節目、発見で得る |
| 交換先 | 神託回復アイテム、探索アイテムの2系統だけ |
| 新個体発見 | 最初から全員見せず、`???` と気配を置く |
| 初回体験 | 最初の神託だけ無料扱いにして、学習コストを下げる |

## 神託回数リソース案

### 基本ルール

| 項目 | 提案 |
|---|---|
| リソース名 | 神託回数 |
| 最大値 | 3 |
| 初期値 | 3 |
| 消費対象 | `Bless` = 1、`Test` = 1、`Watch` = 0 |
| 自然回復 | MVP暫定では 30 tick ごとに 1 回復、または神託回数を消費した解決2回ごとに +1 |
| アイテム回復 | 回復アイテム使用で 1 回復 |
| 0 のとき | `Watch` は可能、`Bless` / `Test` は不可 |

最大値を 3 にする理由は、少なすぎて窒息せず、多すぎて無限に近くもならない最小ラインだからです。

MVPでは、複雑なスタミナ式よりも「今は 3 回まで強い介入ができる」と説明できる単純さを優先する。

### 消費タイミング

消費タイミングは、神が結果に責任を持つ行為に寄せる。

- `Watch`: 消費しない
- `Bless`: 決定した時点で 1 消費
- `Test`: 決定した時点で 1 消費
- 将来の手動ターゲット神託: 1 消費または 2 消費候補

この設計なら、神託回数が 0 でも観察は続けられる。

つまり「何もできず詰む」状態を避けつつ、強い介入だけを有限化できる。

### 自然回復の意図

自然回復は「時間を流して観察する意味」を作るために入れる。

設計意図は次の通りです。

- すぐに介入できない時間があることで、Watch の価値が出る
- 箱庭を眺める時間そのものが、次の強い介入の準備になる
- 神様ポイントが足りない時でも、完全停止にならない

現行実装には `STARTUP_GRACE_TICKS = 12` と `INTERVENTION_COOLDOWN_TICKS = 15` がある。

そのため、自然回復は現行イベント間隔より短くしない。

10 tick ごとに 1 回復すると、次の介入機会までに回復しやすく、神託回数の有限リソース性が弱くなる。

MVP暫定の第一案は、30 tick ごとに 1 回復する形にする。

代替案として、神託回数を消費した解決を 2 回行うごとに +1 回復する形も検討できる。

- 30 tick ごとに 1 回復する
- `Bless` / `Test` など神託回数を消費した解決を 2 回行うごとに +1 回復する

実装時は、`Bless` / `Test` を使う判断が残るように、`Watch` だけで介入回数が簡単に戻りすぎない間隔にする。
`Watch` はイベントを解決する行為ではあるが、神託回数を消費しないため、回復カウントには含めない。

### 初回チュートリアル時の扱い

初回体験では、神託回数の有限性をすぐ罰として感じさせない方がよい。

MVPでは次の扱いを推奨する。

- 最初の 1 回だけ `Bless` または `Test` を無料にする
- 表示上は「初回導き: この神託は消費しない」と伝える
- 無料分を使い切った後に通常ルールへ移行する

これにより、プレイヤーは最初の介入を試しつつ、その後で有限リソースの意味を理解できる。

## 神様ポイントの獲得 / 消費ループ

### 神様ポイントの役割

神様ポイントは、神託回数を直接無限化する通貨ではなく、観察と発見を次の介入へつなぐメタ通貨として使う。

役割は次の3つです。

1. 観察を報酬化する
2. 介入回復を自力で選べるようにする
3. 新個体発見を能動的な目標にする

### 獲得ルール案

MVPでは、神様ポイントは「派手な勝利」だけでなく「見届けたこと」からも得られるようにする。

| 獲得源 | 目安ポイント | 意図 |
|---|---:|---|
| 重要イベントを Watch で見届けた | 0 | 無料の情報収集として扱い、通常のポイント報酬は付けない |
| Watch で未発見の気配や新情報を初めて拾った | 1 | 情報発見だけを少量報酬化し、周回稼ぎにはしない |
| 重要イベントを Bless / Test で解決した | 3 | 神託回数を消費した判断を報酬化する |
| Bless / Test の大成功 | 4 | 良い介入結果を少し強く報酬化する |
| Bless / Test の critical | 5 | まれな大きい結果を報酬化する |
| 節目イベントや季節変化を初回観測した | 8 | 時間を流す価値を作る。ただし周回報酬化しない |
| 新個体を初めて発見した | 15 | 発見を強い報酬にする |
| 新個体の最初の重要イベントに遭遇した | 10 | 発見後の観察を続ける理由を作る |

ポイント量は調整対象だが、MVPでは次の関係だけ守ればよい。

- 回復 1 回分より、発見の報酬をやや大きくする
- Watch は情報収集として前進できるが、通常のイベント解決 3pt の対象外にする
- `Bless` / `Test` を使う動機が残るように、強い報酬は発見、節目、神託回数を消費したイベント解決へ寄せる
- ただし、回復も探索も無限連打できない

Watch は無料で選べる退避行動であり、神様ポイント稼ぎの主手段にはしない。
現行実装では Watch もイベントを解決するため、報酬計算では `Watch 報酬` と `イベント解決報酬` を二重取りさせない。
`重要イベントを Bless / Test で解決した` 報酬は、神託回数を消費した解決だけを対象にする。

Bless / Test は神託回数を消費するぶん、成功時の報酬や成長効果で価値を持たせる。

通常の Watch 報酬は 0pt に留める。

未発見の気配や新情報を初めて拾った時だけ、例外的に `+1pt` 程度を付けてよい。

### 消費ルール案

MVPでの消費先は、まず2系統に絞る。

| 消費先 | 目安コスト | 効果 | MVP |
|---|---:|---|---|
| 祈りの欠片 | 20 | 神託回数を 1 回復する | 入れる |
| 探索の灯 | 40 | 未発見個体を 1 つ探索対象にする | 入れる |
| 観測レンズ | 25 | 気配の情報量を一時的に増やす | 後続 |
| 導きの糸 | 50 | 次に遭遇しやすい対象を寄せる | 後続 |
| 守護の札 | 60 | 次の `Bless` / `Test` に保険をかける | 後続 |

MVPで大事なのは、神様ポイントの最初の使い道を増やしすぎないことです。

最初は次の二択で十分です。

- 今すぐもう一度介入したいので、回復に使う
- 長期的に世界を広げたいので、探索に使う

## 報酬アイテム案

報酬アイテムは、ショップを肥大化させる前に、役割で整理するのがよい。

### MVPで入れるアイテム

| アイテム名 | 役割 | 効果 | 神様ポイント消費 |
|---|---|---|---:|
| 祈りの欠片 | 回復 | 神託回数 +1 | 20 |
| 探索の灯 | 発見 | 未発見個体の探索を 1 回実行する | 40 |

### 後続で広げるアイテム

| アイテム名 | 役割 | 効果 |
|---|---|---|
| 観測レンズ | 情報 | `???` の気配に、属性や気質のヒントを追加する |
| 導きの糸 | 追跡 | 次に注目イベントが出やすい対象を寄せる |
| 守護の札 | 安全策 | 次の介入での事故を和らげる |
| 祝祭の灰 | 加速 | 一定 tick の観察報酬を少し増やす |

MVPでは「介入を増やす」「発見を進める」の2軸だけで十分です。

## 新個体発見の体験案

### 解決したい問題

現状の課題は、観察対象キャラが最初から見えているため、次の感覚が弱いことです。

- 箱庭を広げていく感覚
- 自分で見つけた感覚
- 神様ポイントを探索に使う意味

### 基本方針

最初から全員を名前付きで見せない。

代わりに、世界には最初から次の3状態を置く。

| 状態 | 見え方 | 説明 |
|---|---|---|
| 発見済み | 名前と姿が見える | 通常の観察対象 |
| 気配あり | ぼんやりした光、霧、`???` | 何かいるが、まだ正体は分からない |
| 未探査 | 枠だけ、または何もない | まだ探索していない領域 |

### MVPでの発見フロー

1. 最初は 2 体だけ発見済みにする
2. 残りは `???` スロットまたは薄い気配として置く
3. 観察やイベント解決で神様ポイントを貯める
4. `探索の灯` を交換して使う
5. 新個体が 1 体だけ発見され、名前、役割、短い特徴が開示される
6. 発見ボーナスとして神様ポイントを少し返し、次の観察対象にしたくなる流れを作る

この「一度閉じてから開く」流れが、発見した感じを作る。

### 3D箱庭と一覧での見せ方

MVPでは、発見体験は複雑な演出よりも状態差で出す方がよい。

- キャラ一覧: 発見済みは通常表示、未発見は `???` とシルエット
- 3D箱庭: 未発見個体は名前なしの淡い光や霧としてだけ見せる
- イベント文: 未発見状態では「東側に気になる気配がある」など、対象名ではなく気配で知らせる
- 発見後: 名前、血統、役割のうち最低 2 つを開示する

### read model / UI秘匿のscope

新個体発見は、一覧と3D箱庭だけの表示差分では足りない。

未発見個体の情報は、UIに渡す前の read model / selector 段階で秘匿する。

MVPでscopeに含める面は次の通りです。

| 面 | 秘匿する対象 | 未発見時の表示例 |
|---|---|---|
| `ApostlePanel` 最新イベント要約 | 固有名、血統名、詳細メモ | 「東側に気配があります」 |
| `ApostlePanel` 注目個体 | 名前、状態、役割 | `???` または「未詳の気配」 |
| `ApostlePanel` 血統サマリ | 未発見血統名、生存数、お気に入り数、加護、試練 | 発見済み個体だけ集計し、未発見分は「未詳の気配」に留める |
| `ApostlePanel` 個体一覧 | 名前、血統、特徴 | `???` |
| `ApostlePanel` 裁定結果 | 対象名、血統名、個体詳細 | 「未詳の個体への影響」 |
| `EventModal` title / description | 未発見個体名、血統名 | 「未詳の個体に変化が起きた」 |
| `EventModal` triggerSummary / causeSummary | 名前入りの原因説明 | 「気配の周辺で出来事が起きた」 |
| `EventModal` targetCharacter 表示 | 対象キャラ名、血統 | 「未詳の個体」 |
| `WorldViewport` guide | 未発見個体の総数、名前、血統 | 「気配を追跡中」 |
| `WorldViewport` stats | 未発見数から詳細が逆算できる集計 | 発見済みだけを集計する |
| `WorldViewport` focus label | 未発見個体名 | 「気配を追跡中」 |
| `WorldViewport` controls | 未発見個体名つきのフォーカス操作 | 「気配へ移動」 |
| logs / latestEventSummary / summary | 名前入り文字列、血統名 | 「東側に気配がある」 |

未発見状態では、UIに出してよい情報を `???` と「気配」に制限する。

名前、血統、役割、詳細メモ、関係性、専用イベント名は、発見後に開示する。

内部データとして個体が存在していても、未発見個体の名前・血統・詳細が UI から漏れないことを受け入れ条件にする。

### `???` と「気配」の使い分け

MVPでは、面ごとに次の表現を使い分ける。

| 面 | 表現 |
|---|---|
| 個体一覧 | `???` |
| 3D箱庭 | 淡い光、影、気配 |
| summary / log | 「東側に気配がある」 |
| event | 「未詳の個体」 |
| focus label | 「気配を追跡中」 |
| bloodline summary | 発見済みだけ集計し、未発見分は非表示または「未詳の気配」 |

### 血統サマリの方針

MVPでは、血統サマリは発見済み個体だけで集計する。

未発見個体の血統名、生存数、お気に入り数、加護、試練は表示しない。

未発見の血統がある場合も、血統名を推測できる表示にはせず、「未詳の気配」のような抽象表示に留める。

### 発見後の開示範囲

1体を発見した時は、その個体についてだけ次の情報を開示する。

| 面 | 発見後に開示するもの |
|---|---|
| 個体一覧 | 名前、短い特徴 |
| 3D箱庭 | 通常表示、名前ラベル |
| `ApostlePanel` 注目個体 | 名前、現在状態 |
| `EventModal` | 以後その個体名を表示 |
| 血統サマリ | その個体が属する血統の発見済み分だけ集計 |
| logs / latestEventSummary | その個体については名前つきで記録 |

1体を発見しても、未発見の他個体情報は引き続き秘匿する。

### 後続で足せる発見拡張

- 発見条件を季節や血統に結びつける
- 観測レンズで気配の情報を段階開示する
- 発見した個体ごとに専用の初遭遇イベントを出す
- 既発見個体との関係から連鎖発見を起こす

## MVP最小仕様と後続仕様の分離

### MVP最小仕様

- 神託回数 `3` を導入する
- `Bless` / `Test` だけ 1 消費、`Watch` は 0 消費にする
- MVP暫定では 30 tick ごと、または神託回数を消費した解決2回ごとに 1 回復する
- 初回神託だけ無料にする
- 神様ポイントを観察、節目、発見で配る
- 交換先は `祈りの欠片` と `探索の灯` のみ
- 最初から全員を見せず、`???` と気配を入れる
- 新個体発見で観察対象とイベントの幅が増える

### 後続仕様

- 回復速度や最大神託回数を個別強化で伸ばす
- 複数の探索アイテムを導入する
- 発見の段階開示を増やす
- 発見済み図鑑や発見履歴を持たせる
- 特定個体を狙う探索や、探索失敗リスクを導入する
- 長期保存やセッションを跨ぐ進行を強化する

## 実装PBI候補

### PBI 1: 神託回数MVP

- 目的: `Bless` / `Test` を有限リソース化して、介入判断に重みを持たせる
- 変更範囲: 神託回数の表示、消費、自然回復、初回無料導線
- 受け入れ条件: `Watch` で詰まず、神託回数 0 の状態でも観察ループが続く

### PBI 2: 神様ポイントと最小交換所

- 目的: 観察結果が次の介入や探索に返ってくるメタ報酬ループを作る
- 変更範囲: 神様ポイントの獲得表示、最小交換所、`祈りの欠片` / `探索の灯`
- 受け入れ条件: 観察だけでも少しずつポイントが増え、回復か探索に使える

### PBI 3: PBI-DISCOVERY-VISIBILITY-READ-MODEL-001

- 目的: 発見状態に応じた表示 read model と UI 秘匿を作り、未発見個体の情報漏れを防ぐ
- 変更範囲: 一覧 / 3D箱庭での `???`、気配表示、探索での新個体開示
- 変更範囲: discovery-aware read model / selector / ApostlePanel / EventModal / WorldViewport / 血統サマリ / ログ表示の秘匿
- 受け入れ条件: 初期状態では全員見えず、少なくとも 1 回は「発見して増えた」と感じられる
- 受け入れ条件: 未発見個体は、個体一覧、注目個体、裁定結果、イベント本文、ログ、最新イベント要約のどこにも固有名で表示されない
- 受け入れ条件: 未発見個体の血統、生存数、お気に入り数、加護、試練が血統サマリから逆算できない
- 受け入れ条件: 3D箱庭のガイド表示で、未発見個体の総数やフォーカス名が漏れない
- 受け入れ条件: 未発見状態では `???` と「気配」以外の表現が出ない面が定義されている
- 受け入れ条件: 発見後に開示される属性が、名前 / 血統 / 役割 / 短い特徴 のどこまでか面ごとに定義されている
- 受け入れ条件: 1体発見しても、未発見の他個体情報は引き続き秘匿される

### PBI 4: 発見拡張と上位アイテム

- 目的: 神様ポイントの使い道と発見戦略を中期的に広げる
- 変更範囲: 観測レンズ、導きの糸、守護の札、段階開示
- 受け入れ条件: MVPの単純ループを壊さず、探索と介入の戦略差が増える

## 最終提案

このPBIでは、まず「神託回数 3」「Watch は無料」「神様ポイントの最初の使い道は回復と探索だけ」「新個体は `???` と気配から始める」を中核仕様として固定するのがよい。

これなら、複雑な経済や保存を入れなくても、GodSandbox に次の中長期ループを作れる。

- 介入をいつ使うか考える
- 観察で報酬を得る
- 報酬で次の介入か探索を選ぶ
- 新個体を見つけて、世界が広がる

つまり、GodSandbox は「全部見えている箱庭」から、「限られた神託で少しずつ世界を開いていく箱庭」に進化できる。
