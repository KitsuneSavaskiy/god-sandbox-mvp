# Apostle Tutorial and Opening Design

PBI: `PBI-UX-APOSTLE-TUTORIAL-OPENING-DESIGN-001`

## この設計の目的

ログイン直後の初見ユーザーに、次の4点を短時間で理解してもらう。

1. ここはAIキャラが暮らす箱庭である
2. プレイヤーは観察し、重要な場面で関わる役割である
3. 基本操作は「箱庭を見る」「時間を少し進める」「イベントで選ぶ」である
4. 最初の Bless によって、キャラの命運へ良い影響を与えられる

今回は実装ではなく、初回ショートオープニングと使徒チュートリアルの体験設計を整理する。

## 前提と方針

- 初回体験では、長い説明よりも「何のゲームか」「次に何を押すか」を優先する
- 3D箱庭を早い段階で見せ、世界観の主役をUI説明カードに奪わせない
- チュートリアルは使徒が案内し、説明は短い1から2文に抑える
- 最初の介入体験は Bless に絞り、Watch / Test の詳細学習は後続導線へ回す
- チュートリアルは1回3分未満、初回のみ自動開始、途中スキップ可能、あとで再確認可能にする

## 体験全体の流れ

1. ログイン直後に初回ショートオープニングを再生する
2. オープニングの最後に使徒が現れ、プレイヤーの役割を短く説明する
3. 使徒チュートリアルで箱庭、時間進行、イベント停止、Bless を順番に体験させる
4. Bless 後に寿命が伸びたことを明示する
5. チュートリアル完了報酬を表示し、通常プレイへ戻す

## 初回ショートオープニングの目的

ショートオープニングは、物語を深く語る場ではなく、世界観と目的を最短で理解させる導入にする。

### オープニングで伝えること

- 箱庭ではAIキャラが自律して暮らしている
- プレイヤーは直接操作する主人公ではなく、見守りと介入を行う存在である
- ずっと操作し続けるゲームではなく、変化を見つけて判断するゲームである

### オープニングの長さ

- 15秒から25秒
- 3から4カット
- スキップ可能
- 初回終了後はヘルプやタイトル相当導線から再生できる

### オープニング構成案

#### カット1: 世界の提示

- 見せるもの: 箱庭の全景、生活するキャラ、時間が流れている雰囲気
- 一言メッセージ: 「この小さな世界では、AIキャラが自分の意志で生きています」

#### カット2: プレイヤーの役割提示

- 見せるもの: 少し引いた視点、観察している感覚
- 一言メッセージ: 「あなたは使徒とともに、この世界を見守る観察者です」

#### カット3: 重要イベントの提示

- 見せるもの: 何か異変が起き、時間が止まる演出
- 一言メッセージ: 「大事な出来事が起きたときだけ、あなたの判断が求められます」

#### カット4: Bless 体験への予告

- 見せるもの: 祝福の光、安心に向かう印象
- 一言メッセージ: 「最初の祝福で、ひとりの命運を変えてみましょう」

## 使徒の役割

使徒は、世界観説明と操作案内を担うガイド役とする。

### 使徒が担うこと

- 世界観の翻訳
- 次に押すボタンの明示
- なぜその操作をするのかの説明
- Bless の意味づけ
- 完了時の祝福と達成感の演出

### 使徒の説明トーン

- 偉そうに教えるのではなく、初見を安心させる伴走役
- 長文で設定を語らず、操作と意味をセットで短く伝える
- 正解を押しつけるのではなく、「今日は最初の体験として Bless を試そう」と導く

### 使徒の基本セリフ方針

- 世界観説明: 「ここは、命が育ち、変化していく箱庭です」
- 役割説明: 「あなたは見守り、必要なときだけ選びます」
- 操作説明: 「今はこのボタンを押すと、少しだけ時間が進みます」
- Bless説明: 「Bless は、今ここで助けたい命に手を差し伸べる選択です」

## チュートリアルステップ設計

初回チュートリアルは、強制イベントを含む短い一本道で設計する。
目的は全機能理解ではなく、最初の成功体験を届けることに置く。

| Step | プレイヤーに見せること | 使徒が説明すること | プレイヤーの行動 | 成功条件 |
| --- | --- | --- | --- | --- |
| 1 | 箱庭の全景 | 「ここが箱庭です。まずは暮らしを眺めてみましょう」 | 箱庭を見る | 箱庭画面が表示される |
| 2 | 注目キャラと現在地情報 | 「この世界では、キャラが自分で動きます。あなたは見守る役目です」 | 注目先を見る | 注目キャラが理解できる |
| 3 | 時間進行ボタン | 「このボタンで時間を少し進められます」 | 時間を少し進める | 1回進行する |
| 4 | 重要イベント発生 | 「大事な出来事が起きると、時間は止まり、あなたの判断を待ちます」 | 停止したイベントを見る | イベントが開く |
| 5 | Bless を含む選択肢 | 「今日は最初の介入として Bless を試します。助けたいときの選択です」 | Bless を選ぶ | Bless が選択される |
| 6 | 結果表示 | 「祝福が届きました。寿命が少し伸びています」 | 結果を確認する | 寿命増加が見える |
| 7 | チュートリアル完了 | 「これで最初の役目は完了です。次からはあなた自身の判断で見守れます」 | 報酬を受け取る | 完了状態になる |

## ステップごとの詳細設計

### Step 1: 箱庭を見る

- 目的: まず主役が3D箱庭であることを理解させる
- ハイライト対象: `WorldViewport`
- 使徒の一言: 「ここが命の流れを眺める場所です」
- 注意点: 最初から説明カードを大きく出しすぎず、箱庭そのものを見せる

### Step 2: 注目キャラを見る

- 目的: プレイヤーがキャラを直接操作するのではなく、観察する立場だと理解させる
- ハイライト対象: 現在地カード、注目キャラ表示、ステータス要約
- 使徒の一言: 「誰が今ここで生きているかを、まず把握しましょう」
- 注意点: 数字は多くしすぎず、注目先が1つに見える情報量に抑える

### Step 3: 少し時間を進める

- 目的: 操作の最初の能動体験を作る
- ハイライト対象: 時間進行ボタン、進行状態表示
- 使徒の一言: 「このボタンを押すと、世界が少しだけ先へ進みます」
- 注意点: 長押しや複数速度ではなく、まずは1回の進行だけを体験させる

### Step 4: イベント発生を見る

- 目的: コアループの中核である「観察から判断へ」の切り替わりを理解させる
- ハイライト対象: イベントモーダル、停止理由、対象キャラ
- 使徒の一言: 「大事な変化が起きたので、時間を止めています」
- 注意点: 初見で混乱しないよう、最初のイベントは Bless が自然に選びやすい内容に固定する

### Step 5: Bless を選ぶ

- 目的: 最初の介入が助ける行為だと理解させる
- ハイライト対象: Bless ボタン、簡単な説明文、推奨表示
- 使徒の一言: 「Bless は、この命を支えたいときの選択です」
- 注意点: Watch / Test を並べてもよいが、初回は Bless を推奨状態で見せる

### Step 6: 寿命が伸びる結果を見る

- 目的: 行動と結果の因果をはっきり体験させる
- ハイライト対象: 寿命変化、結果カード、変化の強調表示
- 使徒の一言: 「見てください。寿命が伸び、命運が少し良い方向へ傾きました」
- 注意点: どの数値が増えたかを短く明示し、演出だけで終わらせない

### Step 7: 報酬を受け取る

- 目的: 初回体験を達成感で閉じ、通常プレイに戻す
- ハイライト対象: 報酬カード、受け取りボタン、次にやること
- 使徒の一言: 「これで最初の祝福は完了です。次はあなたの判断で世界を見守ってください」
- 注意点: 報酬表示のあとに、次の自由行動CTAを1つだけ置く

## ハイライトすべきUI箇所

| UI箇所 | ハイライトする理由 | 使徒が伝えること |
| --- | --- | --- |
| 箱庭ビュー | ここが主役の画面だと分かるようにする | 「ここが命の流れを見る場所です」 |
| 現在地カード / 状態要約 | 今どこを見ているか迷わせない | 「今はこのキャラとこの世界の状態を見ています」 |
| 時間進行ボタン | 最初の能動操作を迷わせない | 「このボタンで少し時間を進めます」 |
| イベント停止理由 | なぜ止まったかを理解させる | 「重要な場面なので、あなたの判断を待っています」 |
| Bless ボタン | 最初の正解探しを避けつつ推奨を示す | 「今回は Bless で助ける体験をします」 |
| 寿命変化の表示 | 効果実感を明確にする | 「祝福で寿命が伸びました」 |
| 報酬カード | 達成感と次の行動をつなぐ | 「チュートリアル完了です。次は自由に見守れます」 |

## 使徒が説明する内容の最小セット

チュートリアル中に毎回新しい概念を増やしすぎないため、使徒の説明内容は次の最小セットに絞る。

1. 箱庭とは何か
2. プレイヤーは何者か
3. 時間を進めると何が起きるか
4. なぜイベントで止まるのか
5. Bless はどんな介入か
6. 介入すると結果が変わること
7. 次からは自分の判断で続けてよいこと

## 最初の Bless 体験の設計意図

初回チュートリアルでは、Watch / Bless / Test を完全比較させない。
理由は、初見ユーザーに最初から3択の意味差を覚えさせるより、まず「介入すると世界が変わる」という成功体験を優先したほうが離脱しにくいためである。

そのため、最初のイベントは次の条件を満たすことが望ましい。

- 対象キャラが1体で分かりやすい
- 助ける理由が直感で分かる
- Bless を選ぶ意味が説明しやすい
- 結果として寿命が伸びたことが即時に見える

## 報酬の最小案

最小案は、重い経済設計やバランス変更を伴わず、初回達成の実感を残せるものにする。

### 推奨する最小報酬

- `使徒見習い` のチュートリアル完了バッジ
- 初回完了メッセージ
- 次の自由プレイへ進む明確な CTA

### 理由

- バッジ付与は意味が分かりやすく、ゲームバランスを壊しにくい
- 初回 Bless を体験した証として残しやすい
- 既存のリソース経済が未確定でも導入しやすい

### 将来の拡張案

- Bless に関する一時ボーナス
- 使徒プロフィールや会話の追加解放
- 初回達成記念の観察ログ

## 実装時の注意点

- オープニングは長すぎないこと
- チュートリアル説明が箱庭やボタンを隠しすぎないこと
- 重要な操作は1ステップにつき1つに絞ること
- 初回は Bless までの成功体験を優先し、情報を盛り込みすぎないこと
- スキップしても通常プレイ不能にならないこと
- 後でヘルプから再確認できること

## 完了イメージ

この設計が実装されると、初見ユーザーはログイン直後に次の理解へ到達できる。

- これはAIキャラを観察する箱庭ゲームである
- 自分は使徒とともに見守り、重要な場面で選ぶ役割である
- 最初は時間を進め、イベントが起きたら Bless を選べばよい
- その結果として、命運や寿命が変わる

ここまで分かれば、通常プレイへ戻ったあとも「何を見て、次に何をするか」で迷いにくくなる。
