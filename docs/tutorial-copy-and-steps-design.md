# 初級チュートリアル文言と手順設計

PBI: `PBI-TUTORIAL-COPY-AND-STEPS-DESIGN-001`

この文書は、Sprint6 の初級チュートリアル実装へ渡すための文言と手順の設計メモです。

目的は、初見ユーザーが3分以内に「新米神様として箱庭を見守り、必要な時に助ける」成功体験へ進めることです。

今回は docs-only です。実装、UI変更、画像追加、package変更、CI変更は行いません。

## 決定事項

- プレイヤーは「新米神様」です。
- チュートリアルでは、使徒が短い言葉で案内します。
- 1ステップで求める操作は1つだけにします。
- 初回の成功体験は「助ける」を選び、良い変化を見ることに絞ります。
- 初見向けの表示では、実装語や仕様語を避けます。
- 初級チュートリアルは、代表キャラ1人を選ぶ導線から始めます。
- 代表キャラ選択後は、箱庭を見る、少し時間を進める、出来事を見る、助ける、結果を見る、報酬を受け取る流れにします。

## 初見に出す言葉

初級チュートリアルでは、次の言葉を優先します。

- 新米神様
- 箱庭
- キャラ
- 見守る
- 助ける
- 試練を与える
- 少し時間を進める
- 起きた出来事を見る
- 良い変化
- 報酬

## 初見に出さない言葉

次の言葉は、初級チュートリアルの主文言には出しません。

- `tick`
- `schema`
- `domain model`
- `provider`
- `payload`
- `internal state`
- `Passport schema`
- `介入`

必要がある場合は、先にやさしい言葉を出します。

例:

- 表示する: 「少し時間を進める」
- 表示しない: `1 tick`

例:

- 表示する: 「どう関わるか選ぶ」
- 表示しない: `介入を選ぶ`

## Watch / Bless / Test の短文表示と ? ヘルプ文言

この表は、Line 4 がイベント選択UIを実装する時の文言正本です。

目的は、画面上の選択肢を短くし、詳しい説明を `?` ヘルプへ逃がすことです。

`Watch` / `Bless` / `Test` は実装上の識別子として扱い、初見ユーザー向けの主表示には出しません。

### 表示名とヘルプ文言

| 実装上の識別子 | 画面の短い表示名 | `?` で開く詳細文 | 初回チュートリアルでの扱い |
| --- | --- | --- | --- |
| `Watch` | 見守る | 今は手を出さず、この子の様子を見ます。 | 補助選択肢。初回では強く押し出さない。 |
| `Bless` | 助ける | 小さな祝福で、この子に良い変化を起こします。 | 初回の主CTA。最初の成功体験に使う。 |
| `Test` | 試練 | 成長のきっかけになる小さな困難を与えます。 | 後続学習用。初回では説明を短くする。 |

### UI実装へ渡す表示ルール

- ボタン本体には、短い表示名だけを出す。
- 詳しい説明は、ボタン右上またはラベル横の `?` から開く。
- `?` はマウスホバーだけに依存せず、スマホではタップで読める前提にする。
- ヘルプ文は1文に収める。
- 初回イベントでは `助ける` を主CTAとして強調する。
- `見守る` と `試練` は選べる場合でも、主CTAより目立たせすぎない。
- `Watch` / `Bless` / `Test` の英語名を併記する場合は、初回チュートリアル完了後の補足に限定する。

### 画面文言で避ける語

次の語は、イベント選択UIの表示名や `?` ヘルプ文には出しません。

- `tick`
- `schema`
- `domain`
- `provider`
- `payload`
- `internal state`
- `介入`

必要な場合は、次のように言い換えます。

| 避ける語 | 初見向けの言い換え |
| --- | --- |
| `Watch` | 見守る |
| `Bless` | 助ける |
| `Test` | 試練 |
| `介入` | どう関わるか選ぶ |
| `1 tick` | 少し時間を進める |

### Line 4向けの実装メモ

- tooltip / help popover / small help sheet のどの形式でもよいが、初期表示は短い表示名を優先する。
- ヘルプ本文を常時表示して、選択カードを長文化しない。
- `助ける` の詳細文は、初回Bless成功体験の説明と同じ方向にそろえる。
- `試練` は罰ではなく、成長のきっかけとして説明する。
- `見守る` は何もしない失敗選択ではなく、今は手を出さない判断として説明する。

## チュートリアル全体の短い説明

初回導入で使う説明は、次の1文を基本にします。

> あなたは新米神様として、小さな箱庭で暮らすキャラを見守り、必要な時だけ助けます。

短くする場合:

> 箱庭のキャラを見守り、必要な時だけ助けるゲームです。

使徒の初回一言:

> ここは、小さな命が暮らす箱庭です。あなたは新米神様として見守ります。

## 初級チュートリアルの成功条件

初級チュートリアルは、全機能を教える場ではありません。

成功条件は次の5つです。

1. 自分は新米神様だと分かる。
2. 箱庭でキャラを見守るゲームだと分かる。
3. 代表キャラを選べる。
4. 助ける選択で良い変化を起こせる。
5. もっと見守りたいと思える。

画面見出し:

### Step 6: 助ける

画面見出し:

## Line 3へ渡す表示要件

Line 3 は、チュートリアル基盤と画面ハイライトを担当する想定です。

渡す要件:

- 1ステップにつき、主CTAは1つだけにする。
- 使徒のセリフは1文、長くても2文にする。
- 説明カードは箱庭ビューを大きく隠さない。
- スマホでは画面下部またはカード末尾に主CTAを置く。
- iOSではダブルクリックを主導線にしない。
- ハイライト対象外は暗くしすぎず、現在地が分かる程度にする。
- スキップしても通常プレイへ戻れる。
- `あとで見る` から再表示できる前提を残す。
- チュートリアル状態は、初級完了、スキップ、あとで見るを区別できる形にする。

Line 3に渡すステップID案:

| id | 意味 |
| --- | --- |
| `intro_role` | 新米神様として始める |
| `select_character` | 代表キャラを選ぶ |
| `view_sandbox` | 箱庭を見る |
| `advance_time` | 少し時間を進める |
| `view_event` | 起きた出来事を見る |
| `choose_help` | 助ける |
| `view_good_change` | 良い変化を確認 |
| `claim_reward` | 報酬を受け取る |

## Line 4へ渡すBless成功体験文言

Line 4 は、最初の助ける体験と結果表示を担当する想定です。

表示方針:

- 初回は「助ける」が自然に見える出来事にする。
- 成功結果は、短く、原因と結果が分かる文にする。
- 数字だけでなく、キャラに起きた良い変化を言葉で伝える。
- 失敗や重い代償は初回チュートリアルでは扱わない。

出来事カード案:

> Ryoが森の奥で迷っています。

状況文:

> 道が暗く、少し不安そうです。今なら助けられそうです。

選択肢:

- 主CTA: `助ける`
- 補助: `見守る`
- 後続学習用: `試練を与える`

初回では、主CTAだけを強く見せます。

結果カード案:

> 助けが届きました。

結果文:

> Ryoは落ち着きを取り戻しました。今日を生きる力が少し戻りました。

報酬文:

> 最初の見守りに成功しました。

報酬CTA:

> 報酬を受け取る

## スキップ / あとで見る文言

スキップは逃げ道として置きますが、主導線にしません。

### スキップ

短い表示:

> スキップ

確認文:

> チュートリアルをスキップしますか？

補足:

> あとでヘルプからもう一度見られます。

実行後:

> チュートリアルをスキップしました。

### あとで見る

短い表示:

> あとで見る

補足:

> 今は箱庭を自由に見られます。必要になったら、もう一度案内を開けます。

実行後:

> 案内はあとで見られます。

### もう一度見る

短い表示:

> もう一度見る

補足:

> 最初の流れをもう一度確認します。

## 表示しすぎないためのルール

- 1カードに入れる使徒セリフは1つだけにする。
- 1カードにCTAを複数並べすぎない。
- 初級チュートリアル中は、Passport外部利用やAI環境構築の詳細を出さない。
- 「見守る / 助ける / 試練を与える」の3語は出してよいが、初回で詳しく比較しない。
- 初回は「助ける」を体験し、残りは通常プレイで学ぶ。
