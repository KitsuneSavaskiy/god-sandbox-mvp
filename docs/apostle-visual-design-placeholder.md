# 使徒ビジュアルとプレースホルダー方針

PBI-UX-APOSTLE-VISUAL-DESIGN-PLACEHOLDER-001 対応ドキュメント

この文書は、GodSandbox の案内役である使徒の見た目、表情差分、チュートリアル内での見せ方、後続で仮実装するプレースホルダー範囲を整理するための設計メモです。

今回は実装しません。画像生成、画像アセット追加、SVG作成、React component追加、CSS追加、チュートリアル実装、オープニングムービー実装は行いません。

---

## 結論

使徒は、初見ユーザーに「ここはどんな世界か」「次に何を押すか」「起きた出来事にどう関わるか」を短く案内する補佐役です。

MVPでは、完成イラストよりも先に、画像なしでも成立する仮アバターと表情名の切り替えだけを用意できる設計にします。

---

## 使徒の役割

### 世界観の案内役

使徒は、ユーザーが「神様のように箱庭を見守る立場である」と伝える役です。

伝えること:

- ここはAIキャラクターが暮らす小さな箱庭である。
- ユーザーは命令者ではなく、見守り、声をかけ、必要な時に関わる存在である。
- キャラクターはユーザーの選択で少しずつ変化する。

### 操作チュートリアルの案内役

使徒は、初見ユーザーが最初に押すボタンを迷わないようにします。

伝えること:

- まずは「少し時間を進める」を押せばよい。
- 変化が起きたら画面の案内を見る。
- 出来事が起きたら、キャラにどう関わるかを選ぶ。

### 神様の補佐役

使徒は、ユーザーの判断を代行しません。判断に必要な状況を整理する補佐役です。

伝えること:

- 何が起きているか。
- 選択肢は何か。
- それぞれの選択がどんな意味を持ちそうか。
- 迷う場合に保留できるか。

### 報酬や達成を伝える役

使徒は、ユーザーの行動によって何が進んだかを伝えます。

伝えること:

- キャラに変化があった。
- チュートリアルが進んだ。
- Bless体験や達成が発生した。
- Character Passport へつながる価値がある。

## 基本デザイン方針

### 年齢感

使徒は、年齢不詳だが若い成人に見える案内役とします。

理由:

- 子どもすぎると補佐役としての信頼感が弱くなる。
- 老成しすぎると初見ユーザーへの親しみやすさが下がる。
- 若い成人程度の印象なら、神聖さと親しみやすさの両方を出しやすい。

### 雰囲気

方向性:

- 落ち着いている。
- 親切で、少しだけ茶目っ気がある。
- ユーザーを責めない。
- 初心者に対して「大丈夫、次はこれです」と案内する。

避けること:

- 威圧的すぎる。
- 偉そうに命令する。
- 常に感情が大きすぎる。
- 説明が長すぎる。

### 神聖さ / 親しみやすさのバランス

神聖さ:

- 光、輪、羽、星、祈りなどを連想できる要素を少量入れる。
- ただし宗教的な記号を強く固定しすぎない。

親しみやすさ:

- 表情は柔らかく、目線はユーザーに向ける。
- 服装は儀式的すぎず、案内役として動きやすそうにする。
- 失敗時にも責めず、次の行動を示す。

### 服装やシルエット

基本シルエット:

- 上半身だけでも認識しやすい。
- 小さな丸アイコンでも「使徒」と分かる。
- 肩まわりに軽いマント、短いケープ、羽根飾りなどを置ける余地を残す。

服装:

- 神殿風、旅の案内人風、星読み風の中間。
- 重い鎧ではなく、軽いローブやチュニック寄り。
- 画面の情報を邪魔しないシンプルな形。

避けること:

- 過度に複雑な装飾。
- 小さい画面で潰れる細かい模様。
- 既存作品の衣装やシルエットの模倣。

### 色の方向性

候補:

- アイボリー: やさしさ、案内役
- 淡い金: 祝福、達成
- 青緑: 落ち着き、観察
- 薄い紫ではなく、必要な場合だけ神秘感の補助として使う

MVPでは、色を厳密に固定しません。将来のビジュアル制作PBIで、UI全体の色と合わせて再判断します。

## 表情差分

表情差分は、将来の画像差し替えに備えた vocabulary として定義します。

ただし、MVPの仮実装では全てを画像で用意しません。最初は表情名だけを切り替え、必要なら丸アイコンの色やラベルだけで表現します。

| 表情 | 用途 | MVP優先度 |
|---|---|---|
| 通常 | 基本案内、常時表示 | 高 |
| 微笑み | 初回歓迎、安心させる案内 | 高 |
| 真剣 | 重要な選択、イベント判断 | 高 |
| 驚き | 予想外の出来事、発見 | 中 |
| 困り | エラー、選択に迷う場面 | 中 |
| 祝福 | 達成、報酬、Bless体験 | 高 |
| チュートリアル成功 | 最初の行動完了、次ステップ解放 | 中 |
| 警告 | 危険、取り返しにくい選択、注意喚起 | 中 |

### MVP最小セット

仮実装で最初に扱う表情は4つまでに絞ります。

- 通常
- 微笑み
- 真剣
- 祝福

理由:

- 使徒の基本人格が伝わる。
- 初回案内、イベント判断、達成演出に対応できる。
- 画像なしのプレースホルダーでも破綻しにくい。

---

## チュートリアル内で使う表情

| 場面 | 使う表情 | 使徒の役割 |
|---|---|---|
| 初回表示 | 微笑み | 安心させ、ゲームの目的を短く伝える |
| 「少し時間を進める」案内 | 通常 | 次に押すボタンを示す |
| 変化発生 | 驚き | 何かが起きたことに気づかせる |
| イベント発生 | 真剣 | キャラにどう関わるか判断する場面だと伝える |
| 選択前の補足 | 真剣 | 選択肢の意味を整理する |
| 選択完了 | チュートリアル成功 | 行動が完了したと伝える |
| Bless体験 | 祝福 | 達成や報酬を明るく伝える |
| エラーや未選択 | 困り | 責めずに、次にできることを案内する |
| 危険な選択 | 警告 | 注意点を短く伝える |

MVPでは、上記すべてを画像で表現しません。表情名、短いラベル、背景色、アイコン色だけで仮に伝えます。

## UI上の表示位置

### スマホ

方針:

- 使徒は画面上部の長い説明役ではなく、カード内の短い案内役にする。
- 重要CTAの近くに小さく表示する。
- 画面下の固定表示は慎重に扱う。コンテンツやボタンを隠す可能性があるため、MVPでは避ける。

候補:

- FirstActionGuide の見出し横またはカード内左上に丸アイコンを置く。
- EventModal 内の説明カード先頭に小さな使徒表示を置く。
- Blessや達成時はカード上部に祝福表情を表示する。

### desktop

方針:

- desktopでは、右側パネルや説明カードに常駐できる。
- ただし画面全体を占有しない。
- 情報量が多いため、使徒は「今見るべき場所」を示す補助にする。

候補:

- ApostlePanel の先頭に仮アバターを置く。
- FirstActionGuide の右側アクションカードに使徒アイコンを置く。
- イベント発生中だけ EventModal 内に表示する。

### EventModal

方針:

- イベント判断時は、使徒を「選択肢の意味を説明する役」として使う。
- ユーザーの選択を急かしすぎない。
- 危険や注意がある場合だけ警告表情にする。

表示案:

- モーダル上部: 表情付きの短い状況説明
- 選択肢の上: 「どれを選んでも物語は進みます」のような安心文
- 警告時: 「この選択はキャラに強く影響するかもしれません」と短く表示

### FirstActionGuide

方針:

- 初回CTAを邪魔しない。
- 使徒は「これは何のゲームか」と「次に何を押すか」を短く支える。

表示案:

- 使徒アイコン + 表情名 + 一言案内
- 例: `使徒: 微笑み` / `まずは少し時間を進めて、キャラの変化を見てみましょう。`

### 将来のショートオープニング

方針:

- 長いムービーではなく、短いカード進行にする。
- 30秒以内に終わる。
- スキップ可能にする。
- 最後は FirstActionGuide のCTAへつなぐ。

表示案:

1. 微笑み: 「ここは小さな箱庭です」
2. 通常: 「あなたはキャラを見守る神様です」
3. 真剣: 「出来事が起きたら、どう関わるか選びます」
4. 祝福: 「育ったキャラは、別のゲームへ連れて行けます」
5. CTA: 「少し時間を進める」

## プレースホルダー仮実装の範囲

### 画像がなくても成立する仮アバター

最小仕様:

- 丸い枠
- 中央に `使徒` または短い記号
- 表情名をテキストで併記
- 背景色だけで状態を変える

例:

```text
[使徒]
微笑み
```

### CSSだけの丸アイコン

最小仕様:

- 画像ファイルを使わない。
- CSSの丸、グラデーション、枠線だけで作る。
- 表情ごとに色を変えすぎない。MVPでは2〜3色に抑える。

表情と色の例:

- 通常 / 微笑み: アイボリー + 淡い金
- 真剣 / 警告: 青緑 + 濃い枠線
- 祝福: 淡い金 + 光の印象

### 表情名だけ切り替える仮UI

最小仕様:

- `expression` のような文字列で表情名を持つ。
- 画像差分がない間は、表情名とaria-labelだけを切り替える。
- 表情名はユーザーに見せてもよいが、専門的になりすぎない。

表示例:

- `使徒は微笑んでいます`
- `使徒は真剣な表情です`
- `使徒が祝福しています`

### 後で画像差し替えできるコンポーネント境界

将来の実装では、使徒表示を小さなcomponentに閉じる。

想定境界:

```text
ApostleAvatar
  props:
    expression
    size
    label
```

このPBIではcomponentを作りません。

後続実装時の注意:

- 画像パスを各画面に直書きしない。
- 表情名と画像pathの対応は一箇所に集める。
- 画像がない表情でもfallbackできる。
- FirstActionGuide / EventModal / ApostlePanel が画像管理責務を持たないようにする。
